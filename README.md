# Northwind ETL Pipeline

An ETL pipeline that extracts the classic Northwind dataset from PostgreSQL,
stages it in Snowflake, and transforms it into a star schema for analytics.

**Flow:** PostgreSQL → CSV → Snowflake stage → Snowflake staging tables → Snowflake star schema

## Architecture

```
Extraction/      Pulls all Northwind tables from PostgreSQL into data/*.csv
Staging/         Creates a Snowflake stage, uploads the CSVs, creates stg_* tables,
                 and COPY INTOs them
Transformation/  Builds dimension tables (customers, products, employees,
                 suppliers, shippers, date) and a fact_sales table
Validation/      Sanity checks against the resulting warehouse
Setup/           One-off database/schema creation SQL
```

### Tables extracted
`orders`, `order_details`, `customers`, `employees`, `shippers`, `suppliers`,
`products`, `categories`

### Star schema produced
- `dim_customers`, `dim_products`, `dim_employees`, `dim_suppliers`,
  `dim_shippers`, `dim_date`
- `fact_sales`

## Setup

1. Clone the repo and install dependencies:
   ```bash
   pip install psycopg2-binary pandas python-dotenv snowflake-connector-python
   ```
2. Copy `.env.example` to `.env` and fill in your PostgreSQL and Snowflake
   credentials:
   ```bash
   cp .env.example .env
   ```
3. Run the pipeline stages in order:
   ```bash
   python Extraction/Extraction.py
   python Staging/satge_creation.py
   python Staging/staging_files.py
   python Staging/staging_empty_tables.py
   python Staging/copyinto_stagingtables.py
   python Transformation/transformation.py
   python Validation/validation.py
   ```

## Notes

- `.env` is gitignored — never commit real credentials.
- `data/*.csv` is gitignored since it's regenerated by `Extraction.py`.
- An `orch.py` orchestrator to chain all stages automatically is planned but
  not yet implemented.
